# Release and GitHub Pages preparation

Nothing has been published, pushed or deployed by this preparation.

## Prepared artifacts

Run `npm run release` from the project root. It tests, builds, audits the site, and creates:

- `release/source/` and `web-parallax-source.tar.gz`: source tree, docs, original demo, notices and reviewed CC0 motion files. MediaPipe binaries are regenerated by `npm ci`.
- `release/site/` and `web-parallax-site.tar.gz`: static build including the pinned Apache-2.0 face model/WASM and third-party notices.
- `release/SHA256SUMS.json`: archive checksums.

Only an explicit list of source directories/files is exported. `.local/`, `.env.local`, `.cert/`, `node_modules/`, old screenshots, downloaded character models and generated build output are excluded from the source export. An unreviewed file in `public/` fails the build; adding a model to .gitignore alone would not prevent Vite from serving/copying it.

## Static hosting

The app has no application backend. GitHub Pages can host this static build over HTTPS. Camera/sensor access still needs the user's permission and compatible hardware/browser; the server never receives camera frames or selected model files.

Vite uses relative asset paths. Runtime MediaPipe URLs are resolved relative to the document, and sample motions/docs/credits use relative paths too. This supports both a site root and a project path such as `https://USER.github.io/REPOSITORY/`. Do not open `index.html` directly via `file://`; use an HTTP(S) server.

## Later, when publishing is explicitly wanted

1. Review [license-audit.md](license-audit.md), the source/site manifests and the prepared folders. Use the source export for a fresh repository; do not upload the entire personal workspace.
2. Create the repository and add the prepared source. No repository has been created by this task.
3. In GitHub repository Settings → Pages, choose **GitHub Actions** as the build source.
4. The prepared `.github/workflows/pages.yml` has only `workflow_dispatch`. Choose its manual run only when publication is intended. Pushing code does not trigger this Pages workflow.
5. The workflow installs with `npm ci`, tests, builds, audits, and uploads/deploys `dist/`. Keep all license files, credits and notices in the deployed site.

See [Vite's official Pages instructions](https://vite.dev/guide/static-deploy) and [GitHub's Pages documentation](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site). No GitHub credentials are embedded in the code.

## Local checks

```sh
npm ci
npm test
npm run build
npm run check:release
npm run preview
```

A browser fullscreen regression check is available for an already-open tab connected via CDP:

```sh
CDP_URL=http://127.0.0.1:9227 APP_URL=http://localhost:5173/ npm run check:fullscreen
```

For Android Chrome, first forward a connected device's `chrome_devtools_remote` socket with `adb forward tcp:9227 localabstract:chrome_devtools_remote`. Wireless connection ports depend on the device and are deliberately not stored in public docs.
